# InChat — 우리 안에서 연결되는 대화

`include + Chat`. 한 컴퓨터에서 서버를 실행하면 **같은 Wi-Fi/LAN** 의 다른 컴퓨터·스마트폰이 내부 IP 로 접속해
실시간으로 채팅하고, 화면(또는 브라우저 탭)을 공유해 방송할 수 있는 로컬 서비스입니다.
유료 서비스·외부 계정·외부 CDN 없이 동작합니다. (폰트도 시스템 폰트 사용)

| 영역 | 기술 |
| --- | --- |
| 프런트엔드 | React 18 + TypeScript + Vite |
| 스타일 | Tailwind CSS v4 |
| 백엔드 | Node.js + Express + TypeScript |
| 실시간 채팅 / WebRTC 시그널링 | Socket.IO |
| 데이터베이스 | SQLite (`better-sqlite3`) |
| 방송·화면 공유 | WebRTC (영상은 브라우저끼리 직접 전송) |
| 패키지 관리 | npm (workspaces) |

> 새 프로젝트라 요청하신 구성을 그대로 사용했고, 변경한 스택은 없습니다.
> 채널 목록·채팅·방송 화면 레이아웃과 로고 사용 방식은 아래 "디자인 메모"를 참고하세요.

## 구현된 기능

- **입장**: 닉네임(2~12자, 한글·영문·숫자·`_`·`-`)을 서버에서 검증. 서버가 발급한 세션(HttpOnly 쿠키)으로 사용자를 식별하며 새로고침 후에도 유지됩니다. 권한은 닉네임이 아니라 세션(사용자 ID)에 묶여 있어 닉네임을 바꿔도 다른 사람의 권한을 가질 수 없습니다.
- **채널**: 생성·목록·검색·입장·퇴장·삭제, 채널별 이름/설명/접속 인원/방송 상태(LIVE). 기본 채널(전체 채팅, 자유 대화, 코딩 스터디, 프로젝트 발표)은 초기 데이터로 생성되고 접속자·메시지 수치는 모두 서버 실데이터입니다.
- **실시간 채팅**: 채널별 Socket.IO room, 닉네임·프로필 색상·시간 표시, 내/상대 메시지 구분, 입장·퇴장 시스템 메시지, 최근 메시지 저장·이전 메시지 페이지 조회, 한글 조합 중 Enter 오전송 방지, Enter 전송 / Shift+Enter 줄바꿈, 빈 메시지·긴 메시지(기본 500자) 차단, 연속 전송 제한·중복 전송 방지, 아래를 보고 있을 때만 자동 스크롤(그 외에는 "새 메시지" 버튼), 연결 끊김/재연결/전송 실패 안내, 서버가 부여한 메시지 ID + `clientId` 로 재연결 시 중복·누락 최소화.
- **방송·화면 공유**: 채널 관리자(또는 관리자가 방송 권한을 부여한 사용자)가 화면/창/브라우저 탭을 공유 → 같은 채널 사용자가 시청하며 채팅. 방송 시작·종료, 음소거, 전체 화면, 권한 거부·공유 종료·연결 실패 안내, 오디오 미포함 시 안내. **방송 중에 다른 채널로 이동하거나 채널을 나가도 방송은 계속**되며(상단 배너에서 방송 채널로 이동·방송 종료), 방송 종료 버튼을 눌렀을 때 종료됩니다.
- **채널 관리**: 공지 등록·상단 고정, 메시지 삭제, 참여자·메시지 옆 **⋮ 메뉴**에서 강퇴 + 재입장 제한(10분/1시간/1일/영구)과 **방송 권한 부여/회수**, 제한 해제, 채널 삭제. 모든 관리 권한은 서버에서 검증합니다.
- **반응형**: 데스크톱은 상단(로고·채널 검색·프로필) / 좌측 채널 목록 / 중앙 방송 / 우측 채팅. 모바일은 방송과 채팅을 세로 배치하고 채널 목록은 접이식 메뉴. 방송이 없는 채널에서는 채팅이 중앙의 주 영역이 됩니다.

## 빠른 시작

### 1) 준비
- **Node.js 20 이상**(LTS 권장, 개발은 22 에서 확인)을 설치합니다. <https://nodejs.org>
  - Windows: 설치 프로그램 실행 후 새 PowerShell 을 엽니다. `better-sqlite3` 는 대부분 미리 빌드된 바이너리를 내려받으므로 Visual Studio 빌드 도구가 필요 없습니다. (설치 오류가 나면 "문제 해결" 참고)
  - macOS: 설치 프로그램 또는 `brew install node`.
- 프로젝트 폴더에서:

```bash
npm install          # 의존성 설치 (client, server 함께)
npm run setup        # .env 생성 + 서버 관리자 코드(ADMIN_CODE) 무작위 생성 (한 번만)
```

### 2-A) 개발 모드 (코드 수정 시 자동 반영)
```bash
npm run dev
```
- 화면: `http://localhost:5173` (Vite) — API·소켓은 Vite 프록시가 서버(3000)로 전달하므로 **같은 Origin** 으로 동작합니다.
- 프런트엔드 코드에는 `localhost` 주소가 하드코딩되어 있지 않습니다. (항상 현재 페이지와 같은 Origin 사용)

### 2-B) 빌드 후 실행 모드 (권장, 프런트엔드와 API 가 같은 Origin/포트)
```bash
npm run build
npm start
```
- 화면·API·소켓 모두 `http://localhost:3000` 에서 제공됩니다.
- 실행 로그에 "같은 네트워크" 접속 주소가 출력됩니다.

### 3) 다른 기기에서 접속
1. 서버 컴퓨터의 내부 IP 확인 — 가장 쉬운 방법: `npm run ip`
   - Windows: `ipconfig` → 사용 중인 어댑터의 **IPv4 주소**
   - macOS: 시스템 설정 > 네트워크, 또는 `ipconfig getifaddr en0` (유선/다른 어댑터는 `en1` 등)
2. 같은 Wi-Fi/LAN 의 다른 기기 브라우저에서 `http://<내부IP>:3000` 접속 → 채팅과 **시청**이 가능합니다.
3. 접속이 안 되면 방화벽을 확인하세요.
   - **Windows**: 처음 실행할 때 나오는 "Windows Defender 방화벽" 창에서 **개인 네트워크 허용** 체크. 놓쳤다면 관리자 PowerShell 에서
     `New-NetFirewallRule -DisplayName "InChat" -Direction Inbound -Protocol TCP -LocalPort 3000,3443 -Action Allow -Profile Private`
     (네트워크가 "공용"으로 분류돼 있으면 "개인"으로 바꾸거나 `-Profile Public` 을 추가)
   - **macOS**: 시스템 설정 > 네트워크 > 방화벽이 켜져 있으면 "node" 의 들어오는 연결을 허용합니다.
   - 공유기/학교·카페 Wi-Fi 의 **AP 격리(클라이언트 격리)** 가 켜져 있으면 기기 간 통신이 막혀 접속·방송 시청이 안 됩니다. 이 경우 서버 PC 에서 모바일 핫스팟을 켜고 접속하는 방법이 있습니다.
   - 서버 컴퓨터에서만 쓰려면 `.env` 의 `HOST=127.0.0.1` 로 바꾸세요.

## 화면 공유와 HTTPS (중요)

브라우저는 화면 공유(`getDisplayMedia`)를 **보안 컨텍스트**에서만 허용합니다.

| 접속 주소 | 채팅 | 시청 | 방송(화면 공유 시작) |
| --- | :---: | :---: | :---: |
| 서버 컴퓨터의 `http://localhost:포트` | ✅ | ✅ | ✅ |
| 다른 기기의 `http://192.168.x.x:3000` | ✅ | ✅ | ❌ (보안 컨텍스트 아님 — 화면에 안내 표시) |
| 다른 기기의 `https://192.168.x.x:3443` (인증서 신뢰 후) | ✅ | ✅ | ✅ (PC 브라우저) |

**브라우저 보안 기능을 끄는 방식(플래그, `--unsafely-treat-insecure-origin-as-secure` 등)은 사용하지 않습니다.**
대신 로컬 CA 를 만들어 서버 인증서에 서명하고, 그 CA 를 각 기기가 신뢰하도록 등록합니다.

### HTTPS 켜기
```bash
npm run cert          # certs/ 에 로컬 CA + 서버 인증서 생성 (localhost, 호스트명, 현재 내부 IP 포함)
# .env 에서 HTTPS=true 로 변경
npm start             # HTTP(3000) 와 HTTPS(3443) 를 동시에 제공
```
- 내부 IP 가 바뀌면(공유기 DHCP 등) `npm run cert` 를 다시 실행하세요. **CA 는 재사용**되므로 기기에 CA 를 다시 설치할 필요가 없습니다.
- 개발 모드(`npm run dev`)도 `HTTPS=true` 면 Vite 가 같은 인증서로 `https://…:5173` 을 제공합니다.
- 접속 후 프로필 메뉴의 **"접속 주소 · 화면 공유 안내"** 에서 현재 접속 가능한 주소와 상태를 볼 수 있습니다.

### 각 기기에 CA 인증서 신뢰 등록
서버가 실행 중이면 다른 기기 브라우저에서 `http://<내부IP>:3000/inchat-ca.crt` 로 **공개 인증서만** 내려받을 수 있습니다.
(`certs/inchat-local-ca.key` 는 CA 개인키이므로 **절대 공유하지 마세요.** `certs/` 는 `.gitignore` 에 포함되어 있습니다.)

- **Windows(Chrome/Edge)**: `inchat-local-ca.crt` 더블클릭 > 인증서 설치 > 현재 사용자 > "모든 인증서를 다음 저장소에 저장" > **신뢰할 수 있는 루트 인증 기관** > 마침. 브라우저를 다시 시작.
- **macOS(Chrome/Safari)**: 파일을 더블클릭해 "키체인 접근"에 추가 > 해당 인증서 더블클릭 > 신뢰 > "이 인증서를 사용할 때: **항상 신뢰**".
- **iPhone/iPad**: Safari 로 `…/inchat-ca.crt` 열기 > 프로파일 허용 > 설정 > 프로파일이 다운로드됨 > 설치 → 그다음 설정 > 일반 > 정보 > **인증서 신뢰 설정** 에서 "InChat Local CA" 를 켭니다. (이 단계를 빼먹으면 신뢰되지 않습니다)
- **Android**: `…/inchat-ca.crt` 다운로드 > 설정 > 보안(및 개인정보 보호) > 암호화 및 사용자 인증 정보 > **인증서 설치 > CA 인증서**. (기기마다 메뉴 이름이 조금 다릅니다)
- **Firefox**: 기본적으로 자체 저장소를 사용합니다. 설정 > 개인정보 및 보안 > 인증서 보기 > 인증 기관 > 가져오기, 또는 `about:config` 의 `security.enterprise_roots.enabled` 를 `true` 로 하면 OS 저장소를 사용합니다.

> 스마트폰 브라우저는 대부분 `getDisplayMedia` 를 지원하지 않아 **방송자는 PC 브라우저**(Chrome/Edge/Firefox)를 권장합니다. 스마트폰은 시청·채팅용입니다.
> 오디오 공유는 브라우저와 공유 대상에 따라 다릅니다. (예: Windows Chrome/Edge 는 "탭"·"전체 화면" 공유 시 오디오 선택 가능, macOS 는 탭 오디오만 지원되는 경우가 많음) 오디오가 없으면 화면에 안내가 표시됩니다.

## 환경 변수 (`.env`)

`.env.example` 을 참고하세요. 비밀값은 `.env`(Git 제외)에만 둡니다.

| 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `HOST` | `0.0.0.0` | 바인딩 주소. `127.0.0.1` 이면 이 컴퓨터에서만 접속 가능 |
| `PORT` | `3000` | HTTP 포트 |
| `HTTPS` / `HTTPS_PORT` | `false` / `3443` | HTTPS 사용 여부/포트 (`npm run cert` 필요) |
| `CERT_DIR` | `./certs` | 인증서 폴더 |
| `DB_PATH` | `./data/inchat.sqlite` | SQLite 파일 |
| `ALLOWED_ORIGINS` | (빈 값) | 같은 Origin 외에 허용할 Origin(쉼표 구분) |
| `ADMIN_CODE` | (`npm run setup` 이 생성) | 서버 관리자 인증 코드. 비우면 기능 꺼짐 |
| `BAN_BY_IP` | `false` | 강퇴 시 IP 도 함께 차단(같은 PC/공유기 뒤 사용자도 막힐 수 있음) |
| `IP_HASH_SECRET` | (DB 에 자동 저장) | IP 해시용 비밀값 |
| `SESSION_TTL_DAYS` | `30` | 세션 유지 기간(사용할 때마다 연장) |
| `STUN_URLS` | (빈 값) | 외부 STUN 서버(쉼표 구분). LAN 에서는 필요 없음 |
| `MAX_VIEWERS_PER_BROADCAST` | `8` | 방송자 PC 보호용 시청자 수 한도 |
| `MESSAGE_MAX_LENGTH`, `MSG_BURST`, `MSG_REFILL_MS`, `MSG_MIN_GAP_MS`, `HTTP_RATE_PER_MINUTE`, `LOGIN_RATE_PER_10MIN`, `LEAVE_GRACE_MS` | 500 / 5 / 1000 / 300 / 300 / 20 / 4000 | 메시지·요청 빈도 제한 등 |

### 서버 관리자
채널 생성자는 자기 채널의 관리자입니다. **기본 채널**(전체 채팅 등)에는 생성자가 없으므로, 서버 컴퓨터 `.env` 의 `ADMIN_CODE` 를 화면 프로필 메뉴 > "서버 관리자 인증"에 입력한 사용자가 모든 채널을 관리·방송할 수 있습니다.

## 데이터베이스

- 파일: `data/inchat.sqlite` (WAL 모드). 테이블: `users`(사용자·프로필), `sessions`(세션 토큰 **해시**), `channels`, `channel_roles`(채널별 권한), `messages`, `notices`(공지), `bans`(이용 제한), `meta`.
- **적용**: 서버 시작 시 자동으로 마이그레이션·기본 채널 시드가 적용됩니다. 수동 적용: `npm run db:migrate`
- **스키마 변경**: `server/src/db.ts` 의 `MIGRATIONS` 배열 **끝에** 항목을 추가하세요(`PRAGMA user_version` 으로 적용 여부 관리). 기존 항목은 수정하지 않습니다.
- **초기화**: 서버를 끄고 `npm run db:reset -- --yes` (모든 사용자·채널·메시지 삭제, 다음 시작 때 새 DB 와 기본 채널 생성). 백업은 서버를 끈 상태에서 `data/` 폴더를 복사하면 됩니다.
- 메시지·세션은 자동 삭제되지 않습니다(세션 만료·정리 작업만 수행). 오래 운영하면 DB 가 커질 수 있습니다.

## 방송 구조와 한계

- Socket.IO 는 채팅과 WebRTC **연결 협상(offer/answer/ICE)** 에만 사용하고, 영상은 WebRTC 로 브라우저 간 직접 전송됩니다.
- 구조: **방송자가 시청자마다 1:1 연결(mesh)** 을 만듭니다. 서버는 영상을 중계하지 않습니다.
- 그래서 시청자 N명이면 방송자 PC 의 **업로드 대역폭과 인코딩 부하가 N배**로 늘어납니다. (시청자당 비트레이트 상한을 약 2.5Mbps 로 설정 → 8명이면 최대 ≈20Mbps 업로드 필요. 실제 부하는 화면 해상도·움직임·기기 성능·Wi-Fi 상태에 따라 크게 다릅니다.)
- `MAX_VIEWERS_PER_BROADCAST`(기본 8)는 방송자 PC 를 보호하기 위한 **보수적인 기본값일 뿐, 검증된 최대 동시 시청자 수가 아닙니다.** 이 저장소에서 자동으로 검증한 것은 소수(1~2명)의 시청자까지입니다. 더 많은 인원이 필요하면 SFU(mediasoup, LiveKit 등) 도입이 필요합니다.
- 같은 LAN 을 가정하므로 STUN/TURN 없이 동작합니다. 서로 다른 네트워크(외부 인터넷) 접속에는 TURN 이 필요할 수 있으며 이 프로젝트는 지원하지 않습니다.
- Chrome 은 개인정보 보호를 위해 ICE 후보에 내부 IP 대신 `xxxx.local`(mDNS)을 쓰는 경우가 있어, mDNS 가 막힌 네트워크에서는 연결에 실패할 수 있습니다. 화면에 "방송 연결 시간이 초과되었습니다" 안내가 표시됩니다.
- **방송이 끝나는 경우**: 방송 종료 버튼을 누를 때 외에는, 화면 캡처 자체가 사라지는 불가피한 경우(방송자 탭 종료·네트워크 단절·브라우저의 "공유 중지" 버튼)와 관리자 조치(방송 권한 회수·강퇴·채널 삭제)뿐입니다. 방송자가 다른 채널로 이동하거나 채널을 나가는 것만으로는 종료되지 않습니다. 단, 방송하는 탭을 닫거나 새로고침하면 캡처가 끊겨 종료되므로 탭은 열어 두어야 합니다.
- 한 탭은 한 번에 하나의 채널에서만 방송할 수 있습니다.
- **방송 권한**: 채널 관리자는 참여자 옆 ⋮ 메뉴에서 "방송 권한 부여/회수"를 할 수 있습니다(채널별). 권한 보유자는 방송만 가능하고 공지·삭제·강퇴 같은 관리 기능은 없습니다. 회수하면 진행 중인 방송도 종료됩니다.

## 보안 요약과 한계

- 세션 토큰: 무작위 256bit, DB 에는 SHA-256 해시만 저장, `HttpOnly; SameSite=Lax`(HTTPS 접속 시 `Secure`) 쿠키. 로그에 토큰/관리자 코드를 남기지 않습니다.
- HTTP 요청과 소켓 이벤트 모두 서버에서 입력값(zod)·권한을 검증. SQL 은 전부 매개변수 바인딩. 메시지는 React 가 텍스트로만 렌더링합니다(HTML 미해석).
- Origin: 요청 Host 와 같은 Origin + `ALLOWED_ORIGINS` 만 허용(HTTP 변경 요청·소켓 핸드셰이크 모두). CSP·`X-Content-Type-Options` 등 보안 헤더 적용.
- 빈도 제한: HTTP(IP당), 로그인, 관리자 인증, 소켓 이벤트, 메시지(버스트 5 + 초당 1, 최소 간격, 같은 내용 반복 차단).
- **익명 세션 방식의 한계(강퇴·재입장 제한)**: 사용자는 계정이 아니라 브라우저 세션으로 식별됩니다. 강퇴된 사람이 쿠키를 지우거나 다른 브라우저/시크릿 창에서 새 닉네임으로 다시 입장하면 **완전히 막을 수 없습니다.** `BAN_BY_IP=true` 로 IP 도 함께 차단할 수 있지만 같은 PC·공유기(NAT) 뒤의 무고한 사용자까지 막을 수 있고, IP 는 DHCP 로 바뀌거나 우회될 수 있습니다. 신원 확인이 필요하면 학번/계정 로그인 같은 별도 인증이 필요합니다.
- 서버 관리자 코드는 서버 PC 에 접근 가능한 사람이 아는 비밀입니다. 유출되면 모든 채널 관리 권한이 노출됩니다. 필요하면 `.env` 에서 값을 바꾸고 재시작하세요(이미 인증된 사용자의 권한은 DB 에 남으므로 `npm run db:reset` 또는 DB 수정이 필요).
- 이 서비스는 **신뢰할 수 있는 로컬 네트워크용**입니다. 인터넷에 그대로 공개하지 마세요.

## 테스트 (종단 간 검증)

```bash
npm run build
npm run e2e
```
임시 DB·포트·인증서로 서버를 띄우고 Chromium(Playwright)과 `socket.io-client` 로 아래를 검증합니다: 두 브라우저 송수신, 채널 격리, 새로고침 후 세션·메시지 유지, 비관리자의 관리 기능 차단, 네트워크 단절 후 재연결·누락 복구, 한글 입력(IME 조합), 모바일 레이아웃, 화면 공유 시작·시청·종료, 보안 컨텍스트(HTTP 내부 IP vs HTTPS). 결과와 스크린샷은 `e2e/output/` 에 저장됩니다.
Chrome 경로가 자동으로 잡히지 않으면 `E2E_CHROME_PATH` 를 지정하세요. (Google Chrome 이 설치되어 있으면 자동 사용)

## 문제 해결

- **`npm install` 중 better-sqlite3 오류**: Node LTS(20/22)를 사용하세요. 미리 빌드된 바이너리를 받지 못하면 Windows 는 "Visual Studio Build Tools(C++ 워크로드)" + Python, macOS 는 `xcode-select --install` 이 필요합니다.
- **포트가 사용 중**: `.env` 의 `PORT`/`HTTPS_PORT` 를 바꾸세요.
- **다른 기기에서 접속이 안 됨**: 같은 Wi-Fi 인지, IP 가 맞는지(`npm run ip`), 방화벽, AP 격리, `HOST` 값을 확인하세요.
- **"보안 연결이 아니라서 화면 공유를 막습니다" 안내**: `https://` 주소로 접속하고 CA 를 신뢰 등록했는지 확인하세요.
- **화면 공유 시 macOS 에서 검은 화면/오류**: 시스템 설정 > 개인정보 보호 및 보안 > **화면 기록** 에서 브라우저를 허용하고 브라우저를 재시작하세요.
- **시청자가 "방송 연결 시간이 초과"**: AP 격리/방화벽/mDNS 차단을 의심하세요. (같은 PC 의 두 브라우저로 먼저 확인해 보세요)
